# 上游工具与上下文超限恢复设计

## 目标

减少 Kiro 上游生成可确定修复的错误工具参数，并阻止确定性的上下文超限错误在备用端点、账号和语义重试层之间被放大。

## 范围

1. 当备用端点返回 HTTP 400，或返回已能识别的客户端校验错误时，立即结束当前降级链。若请求存在更小的历史图片版本，仍只允许现有的一次压缩重试。
2. 工具 Schema 仅修复一一对应、值不变、类型匹配的字段别名。只有目标字段是必填字段、源字段未在 Schema 中声明、目标字段不存在时才移动字段。
3. 必填数组字段若收到字符串，仅当字符串本身是完整合法的 JSON 数组，且转换后通过原始 Schema 时才修复。

## 明确不做

- 不伪造缺失的业务值，例如 `query`、`file_path` 或 `multiSelect`。
- 不把普通自然语言列表猜成数组。
- 不伪造客户端强制但上游未产生的工具调用。
- 不调整首字握手、正常 429 切端点或账号故障转移策略。

## 数据流

上游备用端点响应先进入错误分类。确定性的请求错误直接返回给外层；只有 408、429 和真正的 5xx 瞬态错误继续降级。工具调用在交付客户端前复制到候选值中完成别名或 JSON 数组修复，再使用客户原始 Schema 完整校验；任一约束失败时保持原输入并返回原有错误。

## 客户影响

- 上下文超限请求不再等待 10～15 次无效尝试，能更快获得明确 400，便于 NewAPI 或客户端执行压缩/新建会话。
- 确定性工具修复只改字段名或 JSON 表示，不改字段值。
- 无法确定语义的工具参数继续失败关闭，避免执行错误文件、错误查询或错误交互。

## 验证

- 单元测试覆盖备用端点 400 短路、429/5xx 保持可重试。
- 单元测试覆盖双向字段别名、冲突和类型不匹配仍失败。
- 单元测试覆盖 JSON 数组字符串成功修复、普通字符串及不合 Schema 的数组不修复。
- 运行 Rust 定向测试、完整测试和构建。
