# 自动采购账号预设与 403 清理设计

## 目标

为供应商自动采购后的凭证入库增加三个可配置预设：RPM、已有分组和 403 自动删除。配置只作用于新导入的供应商账号，不改变手工添加账号的行为。

## 配置与管理端

- 保留现有 `rpmLimit` 配置，管理端将其明确标注为“自动采购 RPM 预设”，允许 `0` 表示不限速。
- 保留现有 `groups` 配置，管理端改用项目已有的 `GroupMultiSelect`，选项来自分组管理注册表；允许不选择分组。
- 新增 `autoDeleteForbidden` 布尔配置，默认关闭。管理端使用开关，说明仅针对按此预设导入的供应商账号。
- 保存配置时继续遵循现有只写密钥规则，不在响应或日志中暴露供应商密钥和 Webhook Token。

## 凭证标记与数据流

供应商完成采购后，`credential_from_supplier_key` 使用当前运行时配置生成凭证：

1. 写入 RPM、优先级、分组、来源渠道和昵称前缀。
2. 将 `autoDeleteForbidden` 写入凭证级隐藏字段 `deleteOnForbidden`。
3. 凭证字段默认值为 `false`，因此旧配置、手工账号和其它导入路径保持兼容。

该字段随凭证持久化。修改供应商预设不会追溯修改已经入库的账号，避免一次配置变化批量改变存量账号的删除策略。

## 403 处理

上游请求返回 403 后，沿用现有响应读取和令牌刷新判断。进入最终认证失败处理时：

- 若凭证的 `deleteOnForbidden` 为 `true`，TokenManager 删除该凭证、持久化凭证文件并选择下一可用凭证。
- 若为 `false`，继续使用现有累计失败和禁用逻辑。
- 401 不触发自动删除。
- 删除失败时记录不含密钥的错误，并回退到现有失败计数逻辑，避免请求流程失控。

普通请求和流式请求共用同一处理函数，防止两条链路行为不一致。

## 测试

- 配置测试覆盖新字段默认值、camelCase 序列化、保存与运行时视图。
- 供应商服务测试确认 RPM、分组和 403 删除标记被写入新凭证。
- TokenManager 测试确认只有带标记凭证会因 403 删除，未带标记凭证保持原行为。
- 前端 helper 与 UI contract 测试覆盖新字段提交、RPM 文案、分组下拉和删除开关。
- 完成后运行前端测试和构建、Rust 定向测试及完整 `cargo test`。

## 非目标

- 不回填或批量修改已经入库的供应商账号。
- 不把所有 403 都视为全局删除规则。
- 不修改手工采购数量、Webhook 幂等和测试 Webhook 行为。
