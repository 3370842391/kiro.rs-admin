# 空 EOF 图片降级重试设计

## 背景与证据

2026-07-25 在公网测试站复现了一类稳定失败：Kiro 上游返回 HTTP 200 和
`contextUsage`，但没有正文、thinking 或工具事件，随后直接 EOF。RS 在未向客户端
交付语义输出的前提下重试一次，但第二次发送的请求体与第一次完全相同，因此同样
空响应并最终返回 `upstream_empty_response`。

对应现场的关键数据：

- 输入包含 1243 条消息和 9 张客户端可见图片；转换后的 Kiro 请求包含 13 张历史图片。
- 图片 base64 总量从约 3085 KiB 压缩到约 1456 KiB。
- 已生成约 751 KiB 的二级图片压缩请求体，但空响应重试没有使用它。
- 主请求体约 2.98 MiB，上游报告约 578399 个上下文 token。
- 第一次约 23 秒后空 EOF，第二次约 4 秒后再次空 EOF。

当前 `prepare_retry_request_body` 参数中已经携带 `threshold_retry_body`，但对
`AttemptFailure::EmptyResponse` 仍返回原始 `request_body`。这使空响应重试无法利用
已经安全生成的历史图片降级版本。

## 目标

当首轮流式或缓冲请求完全没有语义输出，并且已有合法的二级图片压缩请求体时，
第二次重试改用二级压缩请求体。正常请求、文本历史、工具历史、当前轮图片和客户端
协议保持不变。

成功标准：

1. 首轮空 EOF 后的唯一一次重试使用更小的历史图片请求体。
2. 任何已经交付正文、thinking 或工具调用的请求都不透明重试。
3. 第二次仍为空时返回真实 HTTP 502，供 NewAPI 或其他网关切换兜底渠道。
4. 不增加重试次数，不形成循环，不重复执行工具。
5. 不影响正常请求的首字、SSE Ping、缓存计量和用量统计。

## 方案

### 重试请求体选择

扩展现有 `prepare_retry_request_body` 的选择规则：

| 首轮失败类型 | 第二次请求体 |
| --- | --- |
| `EmptyResponse` 且存在不同的 `threshold_retry_body` | 二级图片压缩请求体 |
| `EmptyResponse` 且无可用二级请求体 | 原始请求体 |
| `InvalidToolSchema` | 保持现有 Schema 修复请求体 |
| `IncompleteToolJson` | 保持现有原始请求体重试 |
| 其他失败 | 不改变现有策略 |

二级请求体由现有图片预算模块生成，只降低历史图片尺寸和 JPEG 质量。它不得删除图片、
修改当前轮图片、裁剪文本、重排消息、修改工具 ID 或工具结果。

### 安全边界

重试仍受现有 `ToolAttemptState` 和 `ProbationBuffer` 约束，必须同时满足：

- 这是第一轮上游尝试；
- 终止原因为 EOF，或现有策略允许的首轮空响应传输错误；
- 尚未向客户端提交任何语义输出；
- 尚未转发任何工具调用；
- 总共只允许一次透明重试。

收到 `contextUsage`、心跳或非语义协议事件不算已经提交语义输出。它们也不能单独让
一次空响应被判定为成功。

### 错误返回

第二次重试仍没有语义输出时，保持现有行为：在发送 SSE 成功头之前返回 HTTP 502，
错误类型为 `upstream_empty_response`。不得发送成功的 `message_delta` 或
`message_stop`，也不得把空响应伪装成成功。

### 诊断信息

在不记录正文、图片数据或工具参数的前提下增加聚合字段：

- `retry_body_variant=primary|aggressive_image`
- `primary_body_bytes`
- `retry_body_bytes`
- `primary_image_b64_kb`
- `retry_image_b64_kb`
- `upstream_context_tokens`
- `termination`

trace 尝试链应能区分第一次普通请求与第二次图片降级请求，便于判断降级重试是否命中。

## 客户影响

正常请求没有行为变化。只有首轮已经完全失败、且包含可继续压缩的历史图片时，第二次
尝试会降低历史图片清晰度。文本、工具历史和当前轮图片保持完整，因此不会主动破坏
当前操作语义。

失败场景仍会多等待一次受控重试，与当前行为相同；区别是第二次不再重复发送同一个
大请求体。若主要限制来自 578K 级文本上下文而不是图片，二级压缩仍可能失败，此时
继续返回 502，不在本次设计中自动裁剪历史消息。

## 测试

至少覆盖以下回归用例：

1. 首轮 `EmptyResponse` 且存在二级请求体，第二次收到的是二级请求体。
2. 二级请求体不存在或与主请求体相同，空响应重试保持原始请求体。
3. 首轮有正常正文时不触发透明重试。
4. 首轮已转发工具调用时不触发透明重试。
5. 两次均为空时只返回一次 HTTP 502，且没有成功终止事件。
6. 第二次成功时客户端只收到第二次的完整事件序列。
7. `InvalidToolSchema` 和 `IncompleteToolJson` 的现有重试策略不回归。
8. 明确的 `CONTENT_LENGTH_EXCEEDS_THRESHOLD` 二级压缩重试不回归。
9. 1 秒 SSE Ping、首字门控、缓存计量和 usage 测试保持通过。

## 非目标

- 不自动删除或总结历史文本。
- 不删除历史图片或把图片替换为占位文本。
- 不改变当前轮图片质量。
- 不增加第三次重试。
- 不强制切换凭据、端点或模型。
- 不改变 NewAPI 或客户端的任务状态机。
